# 批量短信助手 Android 应用设计

日期：2026-08-16

## 1. 目标

构建一个仅供用户本人侧载使用的 Android 应用。应用从 `.xlsx` 文件或剪贴板导入不超过 100 行的动态表格数据，根据本地保存的短信模板为每一行生成短信，允许用户在发送前编辑数据和单条短信，并通过用户选择的 SIM 卡自动逐条发送。

首版不包含账号、云服务、定时发送、短信送达回执或应用市场发布支持。所有业务数据仅保存在手机本地。

## 2. 开发与兼容环境

- 开发工具：本机 Android Studio，产品版本 `261.26222.65.0-AI`。
- 编译平台：本机 Android SDK Platform Android 17 / API 37，`compileSdk = 37`。
- Build Tools：本机已安装 `36.0.0`；具体版本由 Android Gradle Plugin 选择兼容值。
- Java：构建优先使用 Android Studio 内置 JBR 25。
- 最低系统：Android 8.0 / API 26。
- 首个模拟器目标：本机 API 37.1 Google APIs Play Store x86_64 镜像。
- 真机测试：至少覆盖一台具有实体 SIM 的 Android 手机；双卡选择需要双卡真机验证。

## 3. 技术方案

应用使用 Kotlin、Jetpack Compose、单 Activity 和分层架构：

- UI 层：Compose 页面、导航、运行时权限申请和用户交互。
- 状态层：ViewModel 暴露不可变界面状态，处理导入、表格编辑、模板渲染和发送确认。
- 数据层：Room 保存模板、导入任务、短信草稿、发送任务和发送结果；DataStore 仅保存轻量设置。
- 导入层：Excel 与剪贴板适配器统一输出动态二维表模型。
- 模板层：验证变量并把动态表格行渲染为短信草稿。
- 发送层：可替换的 `SmsGateway` 封装 Android `SmsManager`；前台服务执行持久化发送队列。

各层通过接口隔离。自动化测试使用假的 `SmsGateway`，不会发送真实短信。

## 4. 页面与导航

底部导航包含三个主入口：

1. 发送：导入数据、确认表格、选择模板、确认短信、选择 SIM、启动发送并查看进度。
2. 模板：新增、编辑、删除和选择本地短信模板。
3. 记录：查看每次任务及每条短信的提交状态，筛选失败或状态不确定的项目并手动重试。

发送流程是线性的：

1. 选择 `.xlsx` 文件或从剪贴板粘贴数据。
2. 确认首行识别结果和手机号列。
3. 在可水平、垂直滑动的表格中检查并编辑数据。
4. 选择模板并生成短信。
5. 在可垂直滑动的简洁文本区域列表中检查或编辑每条短信。
6. 通过 Radio Button 选择 SIM 1 或 SIM 2。
7. 查看收件人数、长短信分段数和预计短信总条数，执行一次总确认。
8. 启动后台发送并查看进度。

短信确认页不使用带用户名标题的外层卡片。每条只显示短信文本区域，以及下方的序号、脱敏手机号和“与表同步”选项；姓名若存在，仅作为短信正文的一部分出现。

## 5. 动态表格导入

### 5.1 数据来源

- Excel：首版支持 `.xlsx`，读取第一个可见工作表。
- 剪贴板：支持从 Excel 或表格软件复制的制表符分隔行列；同时兼容常见换行格式。
- 单次导入上限为 100 个数据行。若超过上限，导入被阻止并提示用户缩小范围，不静默截断。

### 5.2 表头判断

应用不预设业务字段。导入时自动判断第一行是否为字段名，并允许用户通过“第一行是字段名”开关纠正：

- 有表头：首行成为动态列名，例如“手机号”“姓名”“金额”；数据从第二行开始。
- 无表头：所有行均为数据，列显示为“列1”“列2”“列3……”；这些名称同时用于模板变量。

重复或空白表头会被规范化为唯一名称。例如第二个“姓名”显示为“姓名_2”，空白列使用对应的“列N”。原始单元格值不因规范化而改变。

### 5.3 手机号列

应用按单元格中符合手机号特征的比例自动推荐手机号列。若识别结果不唯一或用户认为结果错误，用户必须点击列头显式指定手机号列后才能继续。

手机号以字符串处理，保留 `+` 和前导零。发送前只做基本字符与长度验证，不把号码强制限定为中国大陆 11 位格式，以便兼容其他号码格式。

### 5.4 表格编辑

确认表支持水平和垂直滑动。用户可点击单元格进行简单文本编辑。表格编辑保存在当前导入任务中，不回写原 Excel 文件或系统剪贴板。

## 6. 模板与短信草稿

模板包含本地唯一 ID、名称、正文、创建时间和更新时间。模板变量由本次导入的动态列名决定，例如 `{姓名}` 或 `{列2}`。

选择模板后，每个数据行生成一个短信草稿。草稿至少保存：

- 行 ID 和目标手机号。
- 根据表格与模板自动生成的内容。
- 当前展示和最终发送的内容。
- 是否与表格保持同步。
- 是否经过手动编辑。

同步规则如下：

- 新生成的短信默认与表格同步。
- 修改表格或模板时，只重新生成仍处于同步状态的短信。
- 用户直接编辑某条短信后，该条自动取消同步，当前内容得到保护。
- 用户重新勾选同步时，应用立即使用最新表格和模板覆盖当前正文，并继续跟随后续刷新。
- 最终确认发送时冻结手机号和短信正文。已启动任务不受后续表格或模板修改影响。

模板中引用不存在的变量时阻止进入最终确认，并明确列出缺失变量。空短信同样不得进入发送队列。

## 7. SIM 选择与权限

应用读取当前活动的 SIM 订阅并用 Radio Button 展示 SIM 1、SIM 2 及可用的运营商标签。只有一张可用 SIM 时仍显示单选项，但默认选中该 SIM。

发送前按系统版本申请并检查所需权限，至少包括：

- `SEND_SMS`。
- 读取活动 SIM 所需的电话状态权限。
- Android 13 及以上的通知权限。
- 前台服务基础权限和 Android 14 及以上对应的前台服务类型权限。

任一关键权限被拒绝、设备无可用 SIM、所选 SIM 失效或设备不支持短信能力时，阻止启动任务并提供可操作提示。

## 8. 后台发送队列

发送由用户在可见页面点击“确认并发送”后启动。后台执行使用带常驻通知的前台服务，使熄屏或切换到其他应用后队列仍能继续。

面向 API 37 构建时，服务声明 `specialUse` 类型，并通过 `android.app.PROPERTY_SPECIAL_USE_FGS_SUBTYPE` 描述“用户明确确认的本机短信批量发送任务”。服务遵循 Android 的前台服务启动限制，不尝试在无用户操作的后台环境中自行启动。

通知显示已完成数、总数、成功数和失败数，并提供“停止剩余任务”操作。停止只影响尚未提交给系统短信模块的项目；已提交项目无法撤回。

队列默认按顺序每 2 秒提交一条短信。首版不提供发送速度设置。长短信通过 `SmsManager.divideMessage` 拆分，所有分段均收到成功提交结果后，该条短信才标记为“已提交”。

发送状态包括：

- `PENDING`：等待提交。
- `SUBMITTING`：已开始调用系统短信模块，尚未取得完整结果。
- `SUBMITTED`：所有分段均已成功提交给系统。
- `FAILED`：系统明确返回失败。
- `UNCERTAIN`：服务中断后无法确认原 `SUBMITTING` 项是否已被系统接收。
- `CANCELLED`：用户停止后尚未发送的项目。

应用只跟踪提交结果，不请求运营商送达回执。

## 9. 防重复与重试

每条短信在调用系统接口前先以事务方式写入 `SUBMITTING`。如果服务异常重启，遗留的 `SUBMITTING` 项转为 `UNCERTAIN`，不得自动重发，以避免重复短信和重复计费。

`FAILED` 与 `UNCERTAIN` 均不自动重试。记录页允许用户筛选并勾选这些项目，在看到号码和正文后明确执行手动重试。重试创建新的发送尝试记录，保留原结果以便审计。

## 10. 错误处理

- 文件不可读、格式不支持或工作表为空：停止导入并说明原因。
- 数据超过 100 行：阻止导入，显示实际行数与限制。
- 表头识别不确定：展示自动判断结果，要求用户确认。
- 手机号列不明确：要求用户指定，不能直接进入模板步骤。
- 非法号码：在表格中标记具体行；用户修正或排除后才能继续。
- 模板变量缺失：列出变量名并阻止最终确认。
- 短信为空：标记对应行并阻止入队。
- SIM 在发送前失效：阻止启动；发送中失效时将当前条记为失败并暂停剩余队列，等待用户处理。
- 系统短信接口返回错误：保存系统结果码及用户可读说明，不自动重试。
- 数据库或服务异常：保留已落盘状态，停止队列并在通知和记录页中提示。

日志不得记录完整短信正文或完整手机号到系统日志。应用界面中的历史记录属于本地业务数据，允许用户查看完整内容。

## 11. 测试策略

### 11.1 单元测试

- `.xlsx` 和剪贴板解析：有表头、无表头、空行、重复/空白字段、数字格式手机号、日期单元格和超过 100 行。
- 手机号列推荐与号码规范化。
- 模板变量验证和渲染。
- 表格刷新、同步短信更新、手动编辑取消同步和重新同步覆盖。
- 长短信分段结果聚合。
- 队列状态转换、停止、服务恢复、防重复与手动重试。

### 11.2 数据与界面测试

- Room DAO 和事务测试。
- ViewModel 状态测试。
- Compose 测试覆盖导入、表头切换、可编辑表格、模板管理、短信编辑、同步开关、SIM 单选和最终确认。

### 11.3 设备验证

- 自动化测试使用假的 `SmsGateway`，不产生真实短信。
- 使用现有 API 37 模拟器验证界面、数据库和前台服务生命周期。
- 使用实体手机验证真实短信、权限、单卡/双卡、长短信、熄屏持续发送、通知停止及系统错误回调。
- 首次真机验证只向用户自有号码发送一条短短信；验证成功后再逐步扩大批量。

每次交付前执行单元测试、Compose/设备测试（在环境可用时）、Android Lint 和 Debug APK 构建。
