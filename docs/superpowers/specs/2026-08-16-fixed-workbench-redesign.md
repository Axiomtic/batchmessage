# 批量短信助手固定工作台重构设计

日期：2026-08-16

## 1. 目标与范围

本设计替换原设计中的多入口、分步骤发送界面。应用只支持手机竖屏；除完整模板管理外，数据编辑、导入、现场模板编辑、短信预览、SIM 选择和发送入口全部集中在一个固定高度的主工作台中。

本次重构不改变既有的 `.xlsx`/剪贴板解析规则、100 行限制、系统短信网关、发送冻结规则和本地数据原则。发送队列、历史记录等后续能力继续复用原设计 `2026-08-16-android-bulk-sms-design.md` 的约束。

## 2. 主工作台布局

主页面本身不得上下滚动。界面从上到下固定分为：

1. 顶部应用栏：显示“批量短信助手”和“模板管理”入口。
2. 数据表格区：约占可用内容高度的 35%，包含紧凑工具栏和可编辑表格。
3. 现场模板区：约占可用内容高度的 20%，包含模板选择、正文编辑、覆盖保存和另存为。
4. 待发送短信区：占剩余主要空间，区域内部垂直滚动。
5. 底部发送区：固定显示 SIM Radio Button、待发送数量和“确认并发送”。

表格区域自身支持横向和纵向滚动；短信列表只在自身区域内滚动。顶部栏、模板编辑区和底部发送区不跟随这两个滚动区域移动。

在不同竖屏高度上使用 Compose `weight` 和最小高度约束分配空间，不通过整页滚动兜底。极小屏幕优先保证工具栏、模板按钮、SIM 选择和发送按钮可见，表格与短信列表减少可视行数。

## 3. 视觉方案

使用 Material 3 浅色绿色主题：

- 主色为低饱和深绿色，用于顶部栏、主要按钮、选中 SIM 和同步状态。
- 浅绿色用于表头、选中手机号列和可编辑区域提示。
- 页面和输入表面保持白色或极浅绿色，正文使用高对比深色。
- 删除、清空、全部取消同步等危险或反向操作使用克制的红色文字或图标，不使用大面积红色背景。

界面只支持竖屏，在 Manifest/Activity 层锁定 `portrait`。

## 4. 初始表格与直接输入

主页面从首次启动起始终显示表格，不再要求用户先导入。

首次安装默认创建 3 列 × 5 行表格：

| 名字 | 电话 | 服务到期日期 |
| --- | --- | --- |
| 张三 | 13800138000 | 2026-09-30 |
| 李四 | 13900139000 | 2026-10-15 |
|  |  |  |
|  |  |  |
|  |  |  |

“电话”列默认作为手机号列。用户可直接点击任意单元格输入，也可通过工具栏增加/删除行列和清空表格。新增列使用数字列名“4、5……”；无表头导入仍按原规则显示“列1、列2……”。

列宽不是固定值。每列根据表头与该列当前最长内容动态计算，并设置最小和最大宽度；内容或表头变化后立即重新计算。列宽总和超过表格区域时使用区域内部横向滚动。

## 5. 导入覆盖行为

Excel 和剪贴板导入按钮始终可见。如果当前表格存在任意非空数据，导入解析成功后先显示覆盖确认：

- 明确说明新数据将替换当前表格。
- 仍处于“与表同步”的短信按新表格和当前模板重新生成。
- 已取消同步的短信正文保持不变；能按原行 ID 对应新表格的短信仍保留重新同步能力。
- 已取消同步但已无对应新行的短信作为独立短信保留，不能自动恢复同步，除非用户删除或重新建立对应关系。

取消确认不得改变当前表格和短信。解析错误或超过 100 行时不弹覆盖确认，直接显示原有导入错误，已有数据保持不变。

## 6. 模板与实时生成

首次安装内置模板：

- 名称：`服务到期提醒`
- 正文：`您好，{名字}，您的服务将于{服务到期日期}到期，请及时办理续期。如已办理，请忽略本短信。`

主工作台中的现场模板编辑器直接编辑当前模板副本。正文每次变化时立即验证变量，并实时刷新所有仍与表同步的短信；手动编辑且已取消同步的短信不受影响。

现场编辑器提供：

- “覆盖保存”：保持当前模板 ID，更新名称/正文和更新时间。
- “另存为”：要求输入新名称，创建新的模板 ID，并立即选中新模板。

顶部“模板管理”进入唯一独立页面。该页支持新建、选择、编辑、覆盖保存、另存为和删除，返回后主工作台保持原有表格与短信滚动状态之外的业务状态。

## 7. 短信同步规则

每个有数据的表格行都应立即出现一条待发送短信。短信正文区域可直接编辑，不增加用户名标题或用户名外框。

- 新短信默认勾选“与表同步”。
- 修改表格、手机号列或现场模板时，只覆盖同步短信。
- 手动修改短信正文后自动取消同步。
- 单条重新勾选同步时，立即用当前行和当前模板覆盖正文。
- “全部取消同步”保护当前所有短信正文。
- “全部同步”对仍有对应数据行的短信重新生成正文；没有对应行的独立短信保持不同步并给出简短提示。
- 导入覆盖后，同步短信使用新数据重建，取消同步短信按第 5 节规则保留。

## 8. 持久化与首次启动

Room 保存一个当前工作区快照，至少包含：

- 当前原始二维表、表头状态和手机号列。
- 当前导入任务 ID。
- 当前模板 ID、现场编辑正文和模板名称。
- 短信草稿正文、同步状态和手动编辑状态。
- 最近选择的 SIM subscription ID（如果下次启动仍可用）。

表格、模板、草稿同步状态和 SIM 选择发生变化时异步保存。再次打开应用时优先恢复最后一次工作区和草稿；只有数据库中不存在工作区时才写入张三、李四和默认模板，之后不重复覆盖用户内容。

数据库升级必须提供从现有版本到新版本的迁移，并继续导出 Room schema。

## 9. 发送入口

底部使用 Radio Button 展示当前可用 SIM。发送按钮始终可见，显示当前待发送条数。点击后继续使用原设计的最终确认与冻结队列规则：展示收件人数、短信分段数、所选 SIM 和不可撤回提醒；未选择有效 SIM、存在非法号码、缺失模板变量或空短信时阻止发送。

本次界面重构不得直接调用真实短信作为自动化验证；测试继续注入假的 `SmsGateway`。

## 10. 验收标准

- API 37.1 模拟器竖屏中，主页面整体没有垂直滚动语义。
- 初次启动可同时看到表格、现场模板、短信列表标题、SIM 选项和发送按钮。
- 表格与短信列表分别具有内部滚动能力。
- 表格列宽随内容变化，并在总宽度超出时横向滚动。
- 直接修改张三的姓名或到期日期后，对应同步短信立即变化。
- 现场编辑模板时同步短信逐字实时变化。
- 手动短信在取消同步后不受表格、模板或导入覆盖影响。
- 全部同步和全部取消同步按第 7 节执行。
- 导入已有表格时必须确认，取消后数据无变化。
- “覆盖保存”和“另存为”产生不同的模板 ID 行为。
- 重启 Activity 和重启应用进程后恢复上次表格、模板和草稿状态。
- 绿色主题在主要界面和模板管理页一致应用。
