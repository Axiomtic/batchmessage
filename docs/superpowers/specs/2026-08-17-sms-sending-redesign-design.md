# 短信发送页与发送流程重构设计

## 背景

当前应用存在四类直接影响使用的问题：

1. `MainActivity` 在没有申请 `READ_PHONE_STATE` 运行时权限时读取活动订阅，`SimSubscriptionProvider` 捕获 `SecurityException` 后返回空列表，界面因此把“未授权”错误显示成“没有 SIM”，并且授权后不会自动重试。
2. “确认发送”按钮没有接入实际发送入口。底层短信网关、Room 发送队列和发送结果接收器已经存在，但没有组件负责冻结队列、逐条提交和把整体进度传回界面。
3. 短信预览仍沿用“逐条编辑并与表同步”的旧模型，与当前“模板统一生成、勾选决定是否发送”的目标冲突。
4. 页面缺少明确的视觉层级和图标，模板选择使用普通按钮，三个底部导航项甚至以单字代替图标。

本次重构借鉴 LocalSend 的 Material 风格、任务进度表达和完成状态，但不复制其图片资源或页面结构。

## 目标

- 正确申请权限、识别活动 SIM，并明确区分未授权、检测中、无 SIM 和失败状态。
- 模板选择使用标准下拉输入框。
- 模板和短信预览成为两个独立的圆角卡片。
- 完整显示电话号码，不再打码。
- 短信正文只读；每条短信只有一个“是否发送”复选框。
- 提供全选、半选和全部清除。
- 真正提交勾选的短信，并只显示整体进度与最终成功/失败数量。
- 使用本地矢量图标改善三个页面的视觉表达。
- 不修改 Gradle 版本，不新增外部依赖，不要求为本次改动下载新的构建资源。

## 非目标

- 不提供逐条短信编辑。
- 不在预览列表中展示逐条发送状态或失败原因。
- 不实现失败短信的单独重试入口。
- 不复制 LocalSend 的品牌图标、插画或专用资源。
- 不改变 Excel、剪贴板和表格编辑的数据导入规则。

## 页面与图标设计

### 图标来源

使用项目内的 Android Vector Drawable 保存常用 Material 风格路径，通过 Compose `Icon`/`painterResource` 加载。这样可以获得与 LocalSend 接近的简洁图标语言，又不需要增加 `material-icons-extended` 等 Gradle 依赖。

主要图标映射：

- 数据页：表格；Excel/文件导入：文档；剪贴板导入：剪贴板。
- 短信页：消息气泡；模板：文本/模板；预览：列表；发送：纸飞机。
- 设置页：齿轮；SIM 设置：SIM 卡；手机号列：电话。
- 状态：进度、成功勾、失败警示。

底部导航继续显示“数据、短信、设置”文字标签，但图标改为真正的表格、短信和齿轮图标，不再显示“数、短、设”等单字占位符。

### 短信页布局

页面保持竖屏，整体不滚动，内部列表滚动：

1. 顶部标题“短信”带短信图标。
2. 第一张圆角卡片为模板区：模板下拉框、添加/删除模板、保存按钮、电话号码列下拉框、模板正文和变量快捷提示。
3. 第二张圆角卡片为短信预览区，并占据剩余高度：标题、已选数量、全选复选框和只读短信列表。
4. 底部发送区显示当前 SIM、已选数量、发送按钮或发送进度。

模板选择使用 Material 3 的 `ExposedDropdownMenuBox` 和只读 `OutlinedTextField`。字段带下拉箭头，点击字段任意位置均展开模板列表，不再伪装成普通按钮。

### 短信预览

每项显示：

- 顺序号和完整电话号码。
- 只读短信正文。
- 右侧“是否发送”复选框。

预览卡片顶部的复选框有三种视觉状态：

- 所有可发送短信已选：勾选。
- 仅部分已选：半选。
- 没有选择：未勾选。

点击顶部复选框时，如果当前已经全选则清空，否则选择全部。列表不再暴露编辑框、同步开关、“全部同步”或“全部取消”等旧功能。

## 选择状态模型

`SendFlowUiState` 增加 `selectedDraftRowIds: Set<Long>`。该集合只表达当前工作区中哪些草稿会进入下一次发送队列，不写入 `MessageDraft`，因此不需要修改 Room 表结构。

规则：

- 首次生成短信时默认全选。
- 用户可切换单条选择或全选。
- 表格或模板刷新时，仍存在的行保留原选择；新生成的行默认选中；已删除行从集合移除。
- 发送开始后冻结选择并禁用模板、号码列和选择控件，防止发送队列与界面数据发生分歧。
- 没有勾选短信时发送按钮不可用。

`BulkSmsRepository.freezeQueue` 接收选中的行 ID，只把对应草稿复制到持久化发送队列。队列一旦冻结，之后的表格或模板变更不会影响正在发送的内容。

## SIM 与权限流程

### SIM 读取

新增明确的 SIM 检测状态，例如：

- `PermissionRequired`
- `Loading`
- `Available`
- `Empty`
- `Error`

启动时先检查 `READ_PHONE_STATE`：

- 已授权：读取活动订阅。
- 未授权：状态设为 `PermissionRequired`，设置页提供“允许读取 SIM”操作。
- 用户授权后：立即重新读取并刷新列表。
- 用户拒绝：保留说明和再次授权入口，不再错误显示“未检测到可用 SIM”。

`SimSubscriptionProvider` 不再把所有异常静默压缩为空列表。权限不足由调用层预先判断；不支持电话订阅或系统服务异常转换为明确错误状态。

### 发送权限

点击发送后检查 `SEND_SMS`。Android 13 及以上若启动前台发送服务，同时请求 `POST_NOTIFICATIONS`；拒绝短信权限时不创建队列，并在界面显示权限提示。权限通过后才显示最终确认框并冻结队列。

## 发送架构

使用现有 Room 队列和 `AndroidSmsGateway`，新增一个不依赖第三方库的平台前台 `Service` 负责顺序发送：

1. ViewModel 根据当前导入 ID、选中行和 SIM 订阅 ID 调用 `freezeQueue`。
2. 启动前台发送服务，并传入任务 ID。
3. 服务通过 `claimNext` 原子领取下一条短信，将状态改为 `SUBMITTING`。
4. `AndroidSmsGateway` 使用指定 SIM 提交分段短信，并等待系统发送结果广播。
5. 服务把结果写为 `SUBMITTED`、`FAILED` 或 `UNCERTAIN`，然后继续下一条。
6. 没有待发送项目后完成任务并停止服务。

前台通知只显示整体进度，不展示电话号码或短信正文。应用被切到后台时，队列仍可继续；若进程被系统中断，已有的恢复逻辑把当时的 `SUBMITTING` 项标记为 `UNCERTAIN`，避免重复发送。

## 整体进度与结果

ViewModel 观察当前任务的 `send_items` Flow，并派生：

- 总数。
- 已处理数。
- 成功数。
- 失败数；`FAILED`、`UNCERTAIN` 和 `CANCELLED` 均计入未成功数量。
- 是否正在发送。

界面仅显示整体信息：

- 发送中：线性进度条和“正在发送 12/80”。
- 完成：成功图标以及“发送完成：成功 76 条，失败 4 条”。
- 无逐条发送状态、无逐条错误码。

发送期间按钮变为不可用，模板区、SIM 选择和预览复选框同时锁定。发送完成后恢复编辑能力，结果卡保留到用户修改数据或开始下一次发送。

## 错误处理

- 未选择 SIM、未设置电话号码列、没有勾选短信或存在空号码时，不允许开始发送并给出就地说明。
- SIM 在确认前失效时停止创建任务并刷新 SIM 列表。
- 单条发送失败不会中断剩余短信，失败数在最终汇总中累计。
- 前台服务异常终止时不自动重发状态不确定的项目，以避免重复扣费。
- 发送操作继续保留不可撤回与可能产生运营商费用的最终确认提示。

## 源码边界

预计调整：

- `MainActivity`：运行时权限、SIM 重载、实际发送回调。
- `SendFlowViewModel`：选择集合、任务进度和发送入口状态。
- `BulkSmsRepository`/`SendDao`：冻结选中草稿、任务观察和中断恢复。
- 新增发送前台服务：顺序消费队列并更新整体进度来源。
- `SmsScreen`、`MessageReviewScreen`、`SettingsScreen`、`BulkSmsApp`：新交互与图标。
- `res/drawable`：本地 Material 风格矢量图标。
- `AndroidManifest.xml`：注册前台发送服务；保留所需权限。

不更改 Gradle wrapper、Android Gradle Plugin、Kotlin、Compose BOM 或依赖列表。

## 测试策略

- 单元测试：选择集合的全选/半选/刷新规则；冻结队列只包含勾选草稿；整体进度统计；发送失败后继续下一条。
- Compose 测试：模板字段是真正下拉框；完整电话号码可见；正文不可编辑；单条和全选复选框；发送期间控件锁定；整体完成数量。
- Android 测试：权限授权后 SIM 重新加载；权限拒绝显示正确状态；前台服务使用假短信网关消费队列。
- 回归测试：模板增删保存、数据导入和表格编辑、电话号码列与 SIM 选择持久化。
- 实机发送不作为自动测试内容；自动测试始终使用假网关，避免产生真实短信费用。

按照用户当前要求，Codex 实现阶段只修改源码和测试源码，不主动运行 Gradle、Android Studio 或模拟器；构建与测试结果由用户在 Android Studio 中执行后确认。
